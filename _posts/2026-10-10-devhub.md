# Beyond Root
I'm not going to lie I found this machine rather boring as it just showcased a bunch of exploits already seen in previous labs, or simply present a code review that is trivial with LLMs. So instead of going beyond root and taking a deeper look into the tech stack, I decided I'd use this machine as a learning opportunity. I've wanted to learn more Rust and so decided to write an `auto-pwn` for this entire machine in `Rust`. You can find the source [here](https://github.com/0xW1LD/devhub_auto/blob/master/src/main.rs).

## Rust Learning
### Channels and Streams
I could easily automate the first part which was just a bunch of web requests to get remote code execution. However, I decided I wanted the program to catch a reverse shell and use that as an interface to other functions. So I had to teach myself all about establishing TCP connections which was easy enough given that `tokio` has the `net::TCPListener` crate feature. I already knew how to thread processes in Rust using `tokio`, so I threaded this listener.

I still had to figure out how to communicate with the thread asynchronously as I wanted to be able to send multiple commands and receive their outputs. This is where I had to learn about multi-producer single consumer (mpsc) channels. These channels would accept any data sent through them, spawn a new thread, and forward them to the TCPListener. This was the first half of the communication, sending the command. I still had to figure out a way to have the output read by the calling module. This was also done through a channel, this time it was a broadcast channel which would read the command output through the TCP stream into a buffer and sent that buffer through the channel.

## WebSockets
Not going to lie, learning the `tokio_tungstenite` crate was a massive maze for me, the [documentation](https://docs.rs/tokio-tungstenite/latest/tokio_tungstenite/fn.client_async.html) for `async websocket clients` wasn't exactly in depth... I spent a few hours looking around online only to realize I had to read the documentation for the `Tungstenite` crate as the `tokio_tungstenite` crate was only made so that `websocket requests` could be made asynchronously, the actual logic for creating requests, messages, and processing output was in the `Tungstenite` crate all along. Also I almost gave up on this because I wanted to use buffers for receiving messages but I couldn't figure out a way to know when the server was done sending a message. I instead just added a timeout and assumed that the full output from the server was received.

## Port Forwarding
I gave up on figuring out how to do this natively, i.e. making a Rust client and yeeting it into the target. Instead I just gave it `ssh`, because why not. Though I did learn about child process dropping which is useful.

## Takeaways
Learning to program is hard, it takes a lot of time and dedication to learn the right patterns and libraries. I feel that we're truly standing on the shoulders of giants given all the available libraries like `Tokio,Anyhow,Clap,Reqwest etc`. Overall I found the process of writing this autopwn more fun that the actual box itself as I learnt a lot more by giving myself this challenge. And I think that's the beauty of the HackTheBox platform, a box can be much harder if you give yourself certain challenges, but it can also be much easier if you do it with friends, or ask for hints along the way. Unfortunately a lot of users choose to take the easiest route and just point their LLM at the box, but where's the fun in hacking when all boxes are "very easy" to you(r LLM). I'm not anti-LLM or anything I just think they're a tool that can be useful on certain occasions like code analysis, but if you abuse the tool then what are you actually learning from a learning platform?
